# cjacksrc

*Contract J.A.C.K.* (Monolith, 2003), built from source.

Monolith never released Contract J.A.C.K.'s source, as it did for *No One
Lives Forever 2*. This project reconstructs it: the game code from NOLF2's
source release (Contract J.A.C.K. was built from the same tree,
`C:\proj\to2\source\Game\`, as its binaries' strings show), and the
engine from the LithTech Jupiter engine source (the 2006 distribution of
the same engine line, built with the same compiler), each brought to what
the retail binaries are, function by function. As for
[nolfsrc](https://github.com/nolffan/nolfsrc) and
[nolf2src](https://github.com/nolffan/nolf2src), the aim is two builds:

- **legacy**: Contract J.A.C.K. (Europe) at its last update, 1.1, rebuilt
  so that it compiles back to the retail binaries byte for byte, as far as
  that can be done -- with the compiler Monolith used, Visual C++ .NET 2003
  (13.10.3077), under Wine;
- **modern**: the same source with fixes and new features (`CJACK_MODERN`).

Compiling back to the retail bytes means compiling the retail game's bugs as
well; their fixes go behind `CJACK_MODERN`, into the modern build only, so
the legacy build keeps matching the retail one.

## Where it stands

Started. The retail game is installed from its discs and update (`ext/rez/`),
the compiler is in `ext/toolchains/` (`msvc-7.10-3077`), and the scoreboard
scores every retail binary against our build. `ltmsg.dll` is built (the
retail file but for its link time stamp) and `SndDrv.dll` builds; the rest
is to come. `docs/PLAN.md` is the plan, package by package.

## Building

Needs docker and the submodules (`git submodule update --init`):
`ext/toolchains/` (the compilers), `ext/rez/` (which fetches the European discs from
archive.org and installs the game with its 1.1 update), `ext/tools/` (the
reconstruction tools) and `ext/lithtools/` (whose `lithrez` packs the 1.1
update's data, `assets/`, into `cjacksrc.rez`); and, for `make modern`, `ext/ffmpeg` (FFmpeg n8.1.3,
which the modern build's Bink player is built on, by `build/ext.sh`).

```sh
make            # out/cjack-legacy-release/: what is built so far, with the retail data
make progress   # score the build against the retail binaries
make help       # everything else
```

Each build also makes two archives of its game directory
(`build/package.sh`): `out/<name>-private.tar.gz`, with the retail game's
data, for your own machines, and `out/<name>-public.tar.gz`, without
the discs' data, to give to other people (it carries only the free 1.1
update's, as `cjacksrc.rez`: `assets/README.md`). The public one
carries scripts that copy the rest out of the player's own images of both
discs (European or USA; a plain `.iso`, redump's `.bin`/`.cue` or its
`.zip`), checking every file they write (`ext/tools/mkinstall.py`):

```sh
cjack-modern-release/linux-install.sh disc1.zip disc2.zip    # Linux
cjack-modern-release/mac-install.command disc1.zip disc2.zip # a Mac, for CrossOver
```

On Windows, drop the two images onto `windows-install.bat`. Each script
also finds them in the game directory or the one above it by itself
(double-click `mac-install.command` in Finder), and can be run again.

Both archives also carry the scripts that start the game
(`build/game-scripts/`): `linux-run.sh` (starts the game under Wine, in a
prefix of its own; the legacy build's launcher gets the registry values
the retail installer wrote) and `linux-server.sh` (a dedicated server,
headless under `xvfb-run` without a display); each prints its usage with
`--help`. On Windows, start `ContractJack.exe`.

In modern builds, `ContractJack.exe` (and `linux-run.sh`) starts the game
immediately using the launcher's saved settings and arguments, skips the
first-run detail prompt, and waits until `Lithtech.exe` exits. Open
`ContractJackLauncher.exe` for the interactive launcher. Under Wine, use
the same prefix as `linux-run.sh` (`~/.wine-cjack` by default). Legacy
builds keep their original launcher behavior.

The modern build plays the intro movies with its own `binkw32.dll`, built
on FFmpeg, and decodes the characters' speech (MP3) in its own
`SndDrv.dll`, so it needs no codec (`MODERN.md` X-1, EN-50). The legacy
build is the retail game's: it plays the movies with RAD's Bink, which
stalls under some Wine setups, so `linux-run.sh` turns them off
(`+DisableMovies 1`); and under Wine its speech needs Fraunhofer's MP3
codec, since Wine's own (`winemp3.acm`) plays the streamed lines as a drone
of their first samples. `linux-run.sh` installs it into the legacy build's
prefix the first time (`winetricks l3codecx`); with another Wine prefix or
a CrossOver bottle, run `WINEPREFIX=<its folder> winetricks l3codecx` once.
Windows has it already.

## Releases

GitHub Actions (`.github/workflows/public-archives.yml`) builds the four
public archives on every push and pull request. Pushing a tag `v*` makes a
GitHub release of it with the modern build's two public archives
(`cjacksrc-<tag>.tar.gz` and `cjacksrc-debug-<tag>.tar.gz`; a tag with a
hyphen is a pre-release), and every push to `master` whose builds pass
replaces the pre-release `nightly` with that commit's
(`cjacksrc-nightly-<commit>.tar.gz`). The release text is
`.github/release_notes.md`.
